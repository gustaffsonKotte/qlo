# QLO: мини-парсер ранних покупателей

Указываешь монету, пул и время — получаешь CSV с кошельками для дальнейшей проверки.

[English](README.md) · [Открыть QLO](https://t.me/kotte_memescan_bot)

## Что он делает

Скрипт читает историю одного пула PumpSwap или bonding curve на Pump.fun,
находит покупки в заданном интервале и сохраняет адреса покупателей.

Для попадания в список нужна подходящая инструкция покупки, совпадение монеты
и пула, подпись покупателя и положительное изменение принадлежащих ему токенов.

Это самостоятельный учебный пример. Внутренние алгоритмы отбора, группировки,
ранжирования кошельков и торговли QLO в него не входят.

Ранний покупатель ещё не обязательно прибыльный трейдер. Результат — список
адресов, историю которых можно изучить.

## Что нужно

- Python 3.11+.
- Solana RPC с доступом к истории за нужный период.
- Доступ к интернету: при запуске загружаются два официальных публичных IDL
  Pump.fun и PumpSwap. Можно передать локальные файлы через --idl.

Сторонние Python-библиотеки для примера не нужны.
RPC-провайдер может брать плату за запросы.

## Запуск

```bash
git clone https://github.com/gustaffsonKotte/qlo.git
cd qlo/examples/early-buyers
export RPC_URL='https://YOUR_SOLANA_RPC_ENDPOINT'
python3 scanner.py \
  --mint YOUR_TOKEN_MINT \
  --market YOUR_POOL_OR_CURVE_ACCOUNT \
  --start 2026-11-04T18:01:00Z \
  --minutes 25 \
  --output buyers.csv
```

Замени значения заглавными буквами на свои.
Дата в команде приведена для примера.

В PowerShell переменная задаётся так:

```powershell
$env:RPC_URL = "https://YOUR_SOLANA_RPC_ENDPOINT"
```

Затем запусти команду python scanner.py с теми же параметрами в одну строку.

| Параметр | Что указать |
|---|---|
| --mint | Контракт монеты, то есть mint |
| --market | Адрес пула PumpSwap или bonding_curve на Pump.fun |
| --start | Начало интервала с часовым поясом; Z означает UTC |
| --minutes | Длительность интервала в минутах |

Контракт монеты и адрес её пула — разные адреса.

Чтобы найти нужный аккаунт, открой транзакцию покупки этой монеты в обозревателе
Solana. В инструкции Pump.fun нужен аккаунт bonding_curve, в инструкции PumpSwap —
pool. Если обозреватель не подписывает роли, они перечислены в официальных IDL
по ссылкам в английской инструкции.

Если монета мигрировала с кривой на AMM, сканируй кривую и пул отдельно.

Скрипт считает секунды от указанного --start. Время запуска монеты он сам
не определяет. Для исследования первых минут укажи реальное время запуска.

RPC_URL читается из переменных окружения. Файл .env автоматически не загружается.
Приватный ключ кошелька не нужен; скрипт только читает данные.

## Что останется после запуска

- buyers.csv: адрес, время первой найденной покупки, секунды от начала интервала,
  число транзакций покупок, полученные токены и ссылка на транзакцию.
- buyers.csv.metadata.json: сведения о полноте сканирования, пропусках и лимитах.

net_tokens_received — сумма чистых изменений токенов у покупателя в найденных
транзакциях. Другие переводы внутри этих транзакций тоже влияют на число.
Это не точный объём исполнения свопов, не текущий баланс и не прибыль.

Покупки в одну секунду не упорядочиваются внутри этой секунды.

## Как читать предупреждения

По умолчанию: до 10 страниц истории, до 200 транзакций и до 250 RPC-запросов.
Повторные попытки тоже расходуют лимит запросов.

Коды завершения:

- 0: история дошла до времени раньше начала интервала; известных пропусков и
  сработавших лимитов нет.
- 2: CSV создан, но полнота данных не установлена или найдены пропуски.
- 1: ошибка настройки, сети или записи файлов.

Пустой ответ провайдера не доказывает полноту истории. Если скрипт не дошёл до
времени раньше начала интервала, он выдаёт код 2. Это возможно и для только что
созданного пула. Проверь поля provider_history_exhausted и
history_reached_before_start в отчёте.

Даже код 0 относится только к выбранному аккаунту, поддержанным инструкциям
и данным, которые вернул RPC. Это не гарантия полной истории монеты.

На активном пуле лимит страниц может закончиться раньше, чем скрипт дойдёт до
нужной даты. Параметры --max-pages, --max-transactions и --max-requests позволяют
поднять ограничения. Расходы зависят от тарифа RPC.

## Что проверять дальше

Открой историю найденного адреса и посмотри:

- реальные продажи и открытые позиции
- убыточные монеты
- зависимость результата от одного удачного токена
- время удержания
- недавнюю активность

Этот пример не считает доходность, не определяет бандлы и не присваивает адресам
статус смарт-кошелька.

Поддержаны покупки базового токена через публичные инструкции Pump.fun/PumpSwap.
Другие DEX, покупатели через PDA, произвольные маршрутизаторы и все варианты
multi-hop находятся вне рамок примера. Подробности — в английской инструкции.

## Проверки

```bash
python3 -m unittest -v
```

Тестовые транзакции синтетические. Они проверяют логику разбора и обработки
пропусков; проверкой реальной RPC-истории эти тесты не являются.
